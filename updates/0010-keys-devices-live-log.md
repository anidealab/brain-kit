# Brain update 10 from AnIdeaLab: the keys table, devices, a live job log, earlier hand-off nudges, agents' work saved as it comes in, and the Mac

Sent 22 Nov 2026. The first update that goes in together the new way: one go brings this brain from the update it's on to this one. It adds a table of the keys the brain already has, a list of the computers it can use with a live check of which are on, a live log of jobs running on the owner's computer, earlier hand-off nudges, a rule that saves each agent's work as it comes in, and the Mac versions of the parts that used to be Windows only.

## Summary for the owner
- **Agents stop asking for keys you've already given.** The brain keeps a table of every key it has (never the keys themselves): which service, when it last answered, and what it's been tested to do. Agents read it before asking you for one. A weekly job checks each key still works, and the weekly tidy-up tells you about any that stopped.
- **Agents know which computer they're on.** The brain keeps a list of the computers it can use, and every chat starts by saying which one it's on. An agent can check in about a minute which of your computers are on and what they're doing, with nothing to set up. The first chat in a new brain asks whether you're on Windows, a Mac or Linux before giving you a command.
- **You can follow a long job on your computer as it runs.** A job's last 80 lines appear on an issue in your brain's repo ("PC job live log") every 30 seconds, so an agent can watch a long render or install instead of waiting for the end.
- **The reminder to start a fresh chat comes a little sooner,** at 250,000 tokens rather than 300,000, and the same for an agent working on a piece of a job. A long chat uses your plan faster and loses detail.
- **Agents' work is saved as it comes in,** so if your plan's usage limit stops a chat, the work its agents finished isn't lost.
- **On a Mac,** the first chat, the upload point and the key script now have their Mac versions.

When it runs, the devices check sends each computer with a runner a tiny job that only reads (its system, GPU, disks, uptime). Nothing else runs on your computer, and there's nothing to paste.

## What changed, and why
1. **The keys table.** Agents kept forgetting keys the owner had already given and asked again. The core's secrets gate, shortened to stay under 6 KB, says to read the keys table before asking for a key; the starting rules say why. `knowledge/systems/keys-and-accounts.md`'s Keys table has fixed columns (Service, Secret, Account, Last check, Can do (as tested), Used for) between `<!-- keys:start -->` and `<!-- keys:end -->`, a note that Last check is only "does it answer", and a list of secrets with no row; long histories go in the new `knowledge/systems/keys-history.md`. New: `.github/workflows/check-keys.yml` (Fridays 12:41 UTC, and by hand), which makes one free, read-only call per key with `skills/add-a-key/check-keys.py` and `key-checks.json`, and writes what it printed to `knowledge/systems/keys-check-log.md` (the last 12 runs); a new step 11 in the brain-audit skill (the weekly tidy-up reads the newest run, gives rows and checks to new secrets, and tells the owner about refused keys); the add-a-key skill says how, and routines.md has its row.
2. **Devices.** Agents couldn't tell which computer a chat was on, which computers were on, or what each could do, and a first chat in the cloud couldn't see whether the owner had Windows, a Mac or Linux. New: `knowledge/systems/devices.md`, a table with a row per computer (the ways in, when it's on, what it's good for, its runner, and in "Spot it" its name); `skills/brain-spec/devices.py` (`here` says which computer this is, `status` which are on now, `list` the table as it reads it); `.github/workflows/devices.yml` ("Which devices are on"), which pings each runner with a tiny job and cancels the pings nobody picks up, so it needs no key, with a check mode on GitHub's machine for an agent with only a run-workflow tool. `reminders.py` prints the device line first. The brain spec has a "Devices" section; getting-started's step 4 asks which computer before giving a command, says there's no Linux command yet, and adds the computer's row after the runner test; the my-pc skill runs the check first when runs sit queued; the weekly tidy-up's new step 12 keeps the list true.
3. **The live job log.** GitHub shows a job's log only when it ends, so an agent couldn't see a long job's progress. `.github/workflows/pc-run.yml` writes the log's last 80 lines to the issue "PC job live log" every 30 seconds and once at the end, with the job's own token (it now has `issues: write`); the first job makes the issue, a public repo skips it, and it never stops the job. The my-pc skill says to read it. The Mac's `mac-run.yml` does the same with "Mac job live log".
4. **Hand-off nudges at 250,000.** `skills/handoff/nudge.json`: the chat's first nudge at 250,000 tokens (was 300,000), later ones still every 100,000, urgent from 500,000; an agent's one nudge at 250,000 (was 350,000). `nudge.py`'s defaults, the handoff skill and the starting rules say the same. Why: a long chat uses the owner's plan faster with every reply and loses detail when it's summarised, and an agent's long run loses detail the same way.
5. **Each agent's work saved as it comes in.** The core's agents default ends "save each one's work as it comes in"; its old reason, "as it uses their plan faster", moved to the starting rules to keep the core under 6 KB. The brain spec's "Handing work to an agent" says how: the brief has the agent commit and push at each milestone, the chat commits what it reports straight away, and a new chat looks for pushed work first. Why: a usage limit can stop a chat and all its agents at any time, and work left only in the chat is lost.
6. **The Mac in the brain's skills.** getting-started's step 4 on a Mac says to pull the Mac parts and follow the my-mac skill's "The first session", and asks for `install.log` if the command stops; the add-a-key, fal, image-to-3d and upload-point skills name the Mac's scripts where they said Windows only. The Mac parts themselves (the my-mac skill, `mac-run.yml`, the Mac's upload point and key script) still come from the Mac command, not from this update.
